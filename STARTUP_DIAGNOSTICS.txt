===============================================
USP CONTROLLER STARTUP DIAGNOSTICS
===============================================

PROBLEM ANALYSIS
---------------

Your startup failed for these reasons:

1. ENCODING ISSUE (SOLVED)
   - Chinese characters caused console encoding errors
   - Result: Batch file commands failed
   - Fix: Replaced all Chinese text with English

2. PORT CONFLICT (MAIN ISSUE)
   - Port 61613 is occupied by RabbitMQ (erl.exe, PID 7468)
   - Mini-Broker cannot start on occupied port
   - Result: Broker startup failed

3. DAEMON FAILURE (CASCADING FAILURE)
   - Daemon tried to connect to broker
   - Broker was not running (failed to start)
   - Result: Daemon exited with code 1


SOLUTIONS
---------

Option A: Stop RabbitMQ and use Mini-Broker
--------------------------------------------
Run in PowerShell (Administrator):
  
  net stop RabbitMQ
  
Then start again:
  
  start_dev.bat


Option B: Use external RabbitMQ instead
---------------------------------------
Skip Mini-Broker and use your existing RabbitMQ:

  start_dev.bat --no-broker

Make sure config.json points to RabbitMQ:
  
  {
    "usp_controller": {
      "broker_host": "127.0.0.1",
      "broker_port": 61613,
      "username": "guest",
      "password": "guest"
    },
    "mini_broker": {
      "enable": false
    }
  }


Option C: Change Mini-Broker port
---------------------------------
Edit config.json:

  {
    "mini_broker": {
      "enable": true,
      "host": "0.0.0.0",
      "port": 61614
    }
  }

Then start normally:
  
  start_dev.bat


STARTUP SEQUENCE
---------------

The script starts services in this order:

1. Mini-Broker (STOMP server on port 61613)
   - If this fails, script aborts
   - Check Daemon console window for errors

2. USP Controller Daemon (new console window)
   - Connects to broker
   - Listens on IPC port 6001
   - If broker is not running, daemon will fail

3. GUI (main window)
   - Connects to daemon via IPC
   - Provides user interface


VERIFICATION STEPS
-----------------

After starting, verify each service:

1. Check Mini-Broker
   - Should see "OK: Mini-Broker started successfully"
   - No error messages about port occupation

2. Check Daemon console window
   - Should see broker connection established
   - No immediate exit

3. Check GUI
   - Window should open
   - Connection status shows "Connected"


COMMON ERRORS
------------

Error: "Port 61613 already in use"
  → RabbitMQ or ActiveMQ is running
  → Solution: Stop it or use --no-broker

Error: "Daemon failed to start (exit code: 1)"
  → Broker is not running
  → Solution: Check broker started successfully first

Error: "GUI cannot connect to daemon"
  → Daemon is not running
  → Port 6001 is occupied
  → Solution: Check Daemon console for errors
